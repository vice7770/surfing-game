## Exact anchor contract

Bootstrap must be tied to the actual just-launched unreaped `Popen` child, with `start_new_session=True`, `pid=pgid`, `proc.poll() is None` both before and after the initial fresh bounded read, and exact predeclared full command equality. The expected command must be declared from the exact launch invocation before reading rows; substring checks and learning the expected command from an arbitrary observed row are forbidden. Actual observed start string is captured in the immutable original leader identity. First read cannot bootstrap from a surviving child, saved PID, prior recipe or reaped leader.

Every nonempty recurring read must satisfy the immutable original leader identity if that leader is present. A changed leader fails even if an unchanged child exists. If the leader is absent, at least one exact member from the immediately previous successful read must still be present BEFORE accepting any updates. A new or changed row alone cannot anchor the group. Only after these checks succeed does the new detached child snapshot replace the prior snapshot. Exited members do not accumulate as stale anchors. Each accepted read must finish later than the preceding read and must not start before that preceding read finished, preventing replay of the same captured rows/timestamps from creating a new observation number.

Child command/start changes inside a freshly anchored group are accepted as current observations, retaining up to16full before/current change records and a total change count. `observation_record` returns detached JSON-compatible current identities, anchor identity and bounded before/current child notes. Anchor failure retains full before/current rows, including the offending leader identity. Group snapshots are bounded to256members and command/start strings to65536/256characters; oversize data fails rather than truncating full identities. These explicit source-only caps require root review against real owner evidence before adoption. Immutable dataclasses and tuples detach accepted snapshots from caller dictionaries.

Empty group is verified absence and never permits signalling. A subsequent nonempty group after verified absence fails. No TERM or KILL is allowed without a NEW successful fresh bounded anchored group read, protected PID intersection check and immediate final freshness/deadline check. The pure signal helper requires the caller's last-signalled observation counter and rejects reuse of that observation or an earlier one; the caller must persist its returned counter after the actual signal. The pure module cannot establish the origin of supplied Popen/read facts or ensure a caller obtains a new read before each signal; root integration must enforce those checkpoints. Full `ps` start strings have finite precision, so this is a bounded identity policy, not proof that same-command PID reuse is impossible.
