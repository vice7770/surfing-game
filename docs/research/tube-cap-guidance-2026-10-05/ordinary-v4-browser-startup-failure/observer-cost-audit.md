# Preserved V3 observer cost audit

This is a read-only audit of the already-written V3 trace/receipts. It does not replay the game or execute a candidate helper, classifier, test, build, browser or listener. `observer-cost-audit.py` generated `observer-cost-audit.json` from the original immutable files; its exact inputs are pinned there.

V3 hit its 640-second native deadline with 1,525 written steps (25.4167 physical seconds) and owner wall elapsed640.99178s. It first pushed at1162, landed at1205 and stood at1234. There were292 standing rows. The last recorded cumulative detector time was5,683.2ms; summed row elapsed detector values were5,685.4ms because individual values are rounded/re-read. Standing detector time sums to5,673.5ms. The120,000ms detector ceiling was not exhausted. Summed published workerStepMs were67,464.2ms (median38.6ms). These metrics do not make a complete wall-time partition.

Source inspection identifies unmeasured observer costs: a normal renderer update/render every physical step; a full37-array/current actor/raw-front/ordinary-surface/tube/drawn-array byte copy and later per-byte comparison each step (bounded8MiB but not timed in V3); status/camera JSON guards and current/input snapshot cloning; per-step browser Runtime.evaluate return/serialization plus native NDJSON persistence; startup, normal menu warmup and the one seeded public restart. Rendering/synchronization and byte guards are plausible costs, but V3 lacks timings to identify which dominates. The classifier's recorded ~5.7s does not explain the640s deadline by itself.

Each standing row computes component bounds/topology and fourteen witness crossings twice, reusing the same seven current physical spheres in the displayed classifier. Across4088sphere calls, only578near triangles reached exact distance evaluation. The earlier per-triangle AABB scan still occurred for each sphere. Zero near triangle candidates does not mean no covering column, no cavity, or a body outside the whole loft bounds: the last V3 witnesses had actual single-crossing ordinary-face coverage and were classified outside the cavity.

V4 therefore keeps all classifier and byte-guard algorithms unchanged. It records browser timings for pilot/input copy, worker drain wall time, mode.update, normal rendering, row copy, guard capture, each current/displayed classifier, criteria, guard verification and total step. Native records step round-trip elapsed time, startup intervals and checkpoint round trips. These are passive timings, with no timing/classification/telemetry feedback to controls. Use future observations to decide whether a safe optimization is justified.
