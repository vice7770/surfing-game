# Coarse foam rejected: complete field path slowed down

The spatial foam prototype was rejected before any visual trial. The complete foam → air sources → aeration → fused snapshot CPU median rose from **5.592 ms** for archived `58ceb6a29` to **5.824 ms** for grouped coverage; the paired saving was **−0.225 ms**. The candidate's unchanged fine default measured 5.184 ms, so this short Node comparison has a module-layout/JIT limitation and establishes no FPS improvement. Grouped coverage was slower than both controls. The exact measurements and guards are in [v2/report.json](v2/report.json).

The prototype grouped visual dense/residual coverage in 2 columns × 4 rows, reducing 116,000 coverage cells to 14,560. Fine source lists, breaking/dissipation, aeration and physical snapshot inputs retained their original cadence and bytes. Foam alone fell from 2.061 to 1.300 ms, but the existing fine-air fallback lost shared departure lookup and the coverage snapshot needed added interpolation. The [patch](prototype/coarse-coverage.patch) was never applied to production. Visual similarity, moving tube behavior and browser FPS were not tested.

The corrected gate held one existing Padang Big captured state fixed: 18 warmup rounds, 30 samples per variant in alternating orders, 20-second bound, no solver steps or GPU calls. Reset/copy, allocation and initialization costs were excluded. Its captured ungated Boussinesq breaking strength was used under all variants because the gated SweptCrash whitewater field was unavailable. Float32 serialized poststate was restored into Float64 arrays; turbulence began at the existing import default of zero. The [source](v2/cost-gate.ts.txt), [compiled bundle](v2/cost-gate.mjs.gz), [authority](v2/authority.json), [compile log](v2/compile.log), [stdout](v2/stdout.json) and empty [stderr](v2/stderr.txt) are preserved unchanged.

The original v1 stopped at intake before collecting any timing. It passed a Node Buffer to the browser Uint8Array decoder; Buffer.slice retained a backing-buffer view where the decoder expected a copying, aligned Uint8Array.slice. The retained raw SET1 breaking strength had zero nonfinite values and range [0,1]. V2 copied the same bytes into `new Uint8Array(raw)` and checked every decoded word against the header's raw offsets before timing. This was harness misuse; it provides no evidence of a historical GPU defect. Both the contradictory initial [failed report](v1-invalid/invalid-input.json) and its [attribution correction](v1-invalid/review.json) remain intact, together with the [v1 source](v1-invalid/cost-gate.ts.txt), [bundle](v1-invalid/cost-gate.mjs.gz), [compile log](v1-invalid/compile.log) and empty [stdout](v1-invalid/stdout.json). The [v2 intake intent](v2/intake-correction.md) records the correction before the new run.

The retained [focused log](validation/focused-tests.log) records 17 passing tests in two files after the final coordinate refinement. The [build log](validation/scratch-build.log) records strict TypeScript and Vite success with the existing large-chunk warning. The frozen [prototype manifest](prototype/manifest.json.gz) also records an earlier 37-test run before that refinement; its separate log was not present and is not invented here. Physical/source/list/air/snapshot parity guards are retained in the patch and v2 source/report. The [prototype intent](prototype/intent.md) describes the pre-cost experiment.

The input fixture remains in the repository at [baseline-held-source.json.gz](../../performance-2026-10-03/render-scale/baseline-held-source.json.gz). The v2 report pins its gzip, expanded JSON and serialized state hashes. Original scripts retain their exact historical absolute input path and report output name; they were not rewritten into portable executable drivers or rerun during this archive. Gzip aliases can be expanded to recover the original bytes; [manifest.json](manifest.json) maps every retained alias to its original path, byte count and SHA-256. Large bundles and the prototype manifest use gzip with an empty filename and mtime 0. The manifest's historical dist-file list is provenance only: browser build assets are not duplicated here. The scratch repository README was unrelated to this experiment and is omitted.
