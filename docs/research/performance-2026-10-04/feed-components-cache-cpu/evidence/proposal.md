# Source-only fixed feed component-count cache

The ordinary packing timer includes a full SideFeed.weights scan solely to read its constructor-fixed component count for the recurring time-block upload. Prior prefetch and sparse-upload sources retain it. This first candidate removes only that one scan. No timing or FPS saving is established by this source proposal.

Canonical runtime remains b0e003b8670c9d0be83bc9bb24c30b5382a54499. Root owns runtime, Git, execution and adoption; this worker owns only this scratch directory. No source tree or held fixture is copied, no dependencies are installed, and no source/library imports, checks, bundling, numerical/browser/physics runs or Git mutations were performed by this worker.

## Exact change and supported semantics

patch-source.mjs makes three unique-anchored substitutions in literal canonical GpuBoussinesq.ts: one integer feedComponents beside feedSlots, capture components from the existing writeFeed deviceShape call, and use feedComponents*3 only at the recurring side-time queue.writeBuffer. SideFeed.count is constructor-fixed even when public weights, window tables and timeOffset change. No component/data arithmetic, clock, queue call/order/byte length, field/grid upload, shader, dispatch topology or solver adoption changes. Exported writeParams remains literal original and continues its fresh mutable slot scan per substep. No per-substep shape cache is added.

The count is refreshed exactly where existing packed tables and feedSlots are refreshed. No-feed and zero-slot paths retain original branches. Public all-zero/restored weights without layout invalidation may retain baseline stale cached dispatch slot/table behavior; the proof preserves that oddity rather than repairing it. The candidate never caches changing public weights.
