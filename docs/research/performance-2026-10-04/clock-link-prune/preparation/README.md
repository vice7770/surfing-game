# Clock-link order after actual SweptCrash pruning

The original `58ceb6a29` code reproduces a clock-link-only lifecycle defect: after a real SweptCrash stall exit, export names IDs that are no longer active, import rejects that export, and the next tracker update can coast those exited IDs back into the front. This synthetic API regression does not attribute the old GPU capture's missing barrel to this defect. Ordinary Padang has clock-link off.

The reproduction uses ordinary public BreakingFront construction with `{jumpReach:10, clockLink:true}`, genuine crest tracking and a genuine end-to-end clock link of two ten-point halves. The left half then crosses its own throw depth; advanceClocks and SweptCrash create its pacing and jets. The test never assigns point metadata. Real ShallowWaterSolver.step(0.01) and PlungingLip.step(0.01) advance physical clocks while the tracker clock is deliberately held by omitting further advanceClocks calls. The untouched watchdog exits IDs0–9 at2.35s, 0.85s after their1.5s pace setup, just after2×touchdown (touchdown0.4223616916493313s). IDs10–19 survive.

Original export still contains matching order IDs0–19 with active IDs10–19. Import throws `A front state whose order names point 0, which it does not hold`. A fresh no-sample tracker update, with no post-prune export first, resurrects paced IDs0–9. The final original regression has three genuine failures; its log and raw evidence are retained under original-regression-final.log and original-proof-final/. The earlier original-regression.log / original-proof/ reflect an initial helper which exported post-prune evidence even in the no-export test. That helper was corrected before both the final original and candidate runs, with identical final test bytes.

The candidate modifies only BreakingFront. Before matching or export, if a separate clock-link matching-order array has a different length from active points, it compacts that order in place against a Set of surviving active object references. Original surviving tie order is retained; only refs removed by in-place crash pruning disappear. It adds no SweptCrash call, watchdog/clock/pacing change, imported-state repair, sorting, sigma change or ray/projection change. The length guard matches the existing supported external operation: SweptCrash only removes active refs in place. Same-length arbitrary caller replacement/addition is not claimed as a new supported mutation contract. Clock-link-off has no separate order and returns immediately.

The final candidate passes65tests in4files: the3new combined regressions plus all existing BreakingFront, sliceClock and SweptCrash tests. This includes the unchanged historical switch-off state fingerprints, handover/tie-order tests, new own-throw crossing tests and the existing actual stall/fade watchdog contracts. No assertion was weakened. Before-prune states, surviving post-prune point/held fields, crash exit refs/time and crash counts were compared exactly between original and candidate evidence; only the intended order membership and resulting later lifecycle differ.

`candidate.patch` contains the one runtime-file patch and the new regression file. `original-BreakingFront.ts` preserves the original runtime source. `original-source-manifest.json` records all source bytes copied from the workspace; all those production hashes remain unchanged, and the scratch changes only BreakingFront plus the added test. `proof-summary.json` and `manifest.json` bind the source, logs, and raw evidence. The scratch has a node_modules read symlink and its own Vitest cache directory. No GPU/browser run, full suite, TypeScript/Vite build or Git operation was performed. This is prepared for root review, not a production adoption.
