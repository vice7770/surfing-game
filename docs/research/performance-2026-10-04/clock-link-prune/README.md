# Clock-link order after real crash pruning

The clock-link lifecycle fix is adopted in the root working tree: the focused regression and existing contracts pass **65 tests in four files**, and the strict TypeScript/Vite build succeeds. The original runtime fails all three new regressions. This is correctness evidence for a synthetic actual-API watchdog fixture with `clockLink: true`; it makes no FPS claim and does not identify a cause of the old GPU capture. Ordinary Padang has clock-link off.

The fixture creates a real 20-point clock-linked front through crest tracking. IDs 0–9 cross their own throw depth, acquire clocks and real SweptCrash pacing, and leave through the unchanged stall watchdog after real solver and lip steps. IDs 10–19 survive. No point metadata is assigned directly. Further tracker clock advancement is deliberately omitted to exercise the existing watchdog; no pacing, watchdog timing, or clock contract is weakened. The exit occurs at 2.349999999999993 s, after pacing starts at 1.5 s; touchdown is 0.4223616916493313 s.

The original matching-order array still contains exited IDs 0–9. Its export has active IDs 10–19 but order IDs 0–19, and the actual importer rejects it with `A front state whose order names point 0, which it does not hold`. A separate fresh tracker update with no post-prune export resurrects exited IDs. The [final original log](validation/original-final.log) and [final original evidence](original-final-proof/export-import.json) retain these failures.
