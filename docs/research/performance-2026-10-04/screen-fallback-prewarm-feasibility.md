**Lazy path.** WaterSurface.ts:514–560 creates fallbackMesh and fallbackPatch on the first supported active mask. They share **one** cloned MeshPhysicalMaterial and the original two geometry objects. Its callback invokes the original callback then replaces WATER_BARREL_DISCARD with WATER_BARREL_FALLBACK_DISCARD; its key appends `-barrel-hole-fallback`. Original water and roof callbacks/keys/materials are preserved (roof: SweptBarrelMesh.ts:304–358). Sync tracks source version/environment/shadow/geometry state. No runtime compile/compileAsync call exists, so the repair family can first be acquired during rendering. Renderer initialization sets stencil/srgb/NeutralToneMapping (main.ts:216–225), but constructor refreshReflection hides the water subtree during its environment cube capture (1036–1070); that capture does not prewarm these still-absent repair children.

Coarse PlaneGeometry has normal (WaterSurface.ts:767); patch has position/skirt/onPatch/index but no normal (water/richPatch.ts:65–108). This establishes possible geometry variants, not how many programs the old live draw actually acquired: a shared material can reuse its current program without getProgram on every object.

**Public API.** Installed primary sources: `WebGLRenderer.js:1358–1569,2187–2303`; `webgl/WebGLPrograms.js:54–61,177–213,309–322,363–386,549–560,628–645`; `webgl/WebGLProgram.js:436,861–1007`, under `node_modules/three/src/renderers/`.

`compileAsync(object,camera,targetScene)` synchronously calls compile, then polls each material's currentProgram. compile uses targetScene's visible lights/camera layers, fog/environment and actual geometry/material parameters; its mesh traversal includes hidden objects and drawRange0. It does not call placePatch/onBeforeRender or renderBufferDirect for these non-node materials. Thus `compileAsync(water.mesh,view,scene)` correctly prepares the allocated subtree against the **current** real scene, without fake visibility/mask/reparenting. Omitting scene as third argument for a Mesh uses an empty scene in getProgram and loses real fog/environment.

However, root traversal can prepare several geometry programs for one material while readiness checks only its **last currentProgram**, not its entire programs Map. To await each repair variant through public APIs, compile the two actual leaf children sequentially. Use null render target, actual srgb/NeutralToneMapping, current lights/environment/look; an offscreen target selects different output/tone mapping. Null above-water fog and underwater FogExp2 are separate variants. Later look/normals/environment mapping or dimensions/shadow counts/dev-view changes can require new programs. One precompile is not all future variants.

Without KHR_parallel_shader_compile, WebGLProgram.isReady is immediately true with the explicit warning that first use may stall; compileAsync merely delays its first check10ms. Even with KHR, getUniforms/getAttributes/onFirstUse still defer uniform/attribute reflection and link/error queries (`WebGLProgram.js:863–990`). Attribute upload is render→objects.update→geometries.update (`WebGLRenderer.js:1901/1916`, WebGLObjects.js:5–20, WebGLGeometries.js:65–77); index/VAO setup occurs in renderBufferDirect (`WebGLRenderer.js:1254`), and uniform/texture binding/upload in render (`2791/2797`, WebGLTextures.js:711/907). Compile-only does not exercise these. Original geometry/textures are shared, so a distinct repair program does **not** imply a second full geometry/texture upload; separate program binding/reflection can still remain.

**Warm rendering is a different experiment.** Zero-draw or wholly discarded rendering may reach program/reflection/setup but proves neither texture nor raster work. An offscreen target can warm the wrong output variant; visibility/drawRange/color/depth/stencil changes can warm a different path. A normal drawPhysical behind loading would exercise fresh mask/roof/fog, FFT/caustics/shadows, textures and binding with the actual output, but does substantially more work and changes prepared render/cache state. It requires separate bounded provenance/validation and is not part of the compile-only proposal.
