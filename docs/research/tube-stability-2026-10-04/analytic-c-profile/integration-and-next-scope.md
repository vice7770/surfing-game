# Shared-provider port plan and minimum next formulation

The frozen candidate supplies a small deterministic construction, not a generic framework. It is not port-ready because the real Reef root crossings, explicit thin-sheet domains, zero-state floor jumps and contact rounding need a separate formulation. Its captured C-shaped passage is a useful reference result, not adoption evidence.

## One minimum structural option, not evaluated here

Replace the single root semicircle constrained to end on a low floor with **a bounded upper turn, straight descending face, and bounded lower turn**. Derive the upper radius from the shared roof/bulk clearance and current thickness; the straight segment supplies the height drop instead of forcing the circle radius to supply it. Both turns and the straight share endpoint tangents. The lower turn attaches to the same analytic floor plane. If the available radius is smaller than the ribbon/thickness feasibility bound, return that domain and explicitly expand the leaf/toe or bulk join; do not choose a reflected tangent or raw frame. This targets the39 real Reef crossings:37 involve both owned roof and bulk, two only bulk, so simply owning all128 would not remove the owned roof conflict.

Use one common floor-parameter limit across ordinary, formation, retirement and retired states. Formation zero and positive limits must have identical control handles, not separately selected de Casteljau versus chord/3 handles. Retirement must continuously evolve its floor direction/handle toward the collapsed broken-face value and solve contact against that same floor; keeping a horizontal plateau until suddenly choosing a vertical retired tangent is discontinuous. Preserve actual cap-floor contact via the shared solve, rather than treating the envelope cap as a stationary fluid particle. A future exact contact projection onto the shared F32 plane is a global geometric constraint, not a parameter change; it must stamp the same cap/floor value for all consumers.

Only after those mathematical limits are identical can a **precision-aware ordinary/collapsed state** be defined. Derive it from the geometric loop's representable dimensions and publish no void/roof false air below precision. The active sheet approaches zero as g² while reach/root approach zero at first order; the declaration currently requires8ULP. The strict failures therefore report loss of a stored paired sheet, not a proven macroscopic air pocket. However this version also has up to0.01240/0.01759h0 floor limit jumps, so substituting its present ordinary branch would be an observable snap. A separate frozen version must specify and test its maximum quantization displacement bound. No such version was tried.

## Exact production entry points to change together

1. `ProfileLibrary.profileAt` currently brackets cases, applies `caseTimes`, samples/interpolates every raw vertex, scales, and returns baked TD/clear/collapse and old tip velocities. For an analytic model, keep raw decoding as source data, extract/blend A/T/tangent/scale/phase parameters first, then call one provider after blending. Preserve the actual query age for formation/sealing/impact/retirement. Clamp only source parameter sampling to available frames, not the analytic age to old TD/held geometry. Drawing and contact must use identical parameter times/geometry. Raw/direct fixtures keep the existing route.

2. `ProfileLibrary.pointAt` currently interpolates only the requested raw landmark separately. It must read the same cached analytic query result/landmark object used by `profileAt`; recreating a different interpolation route would silently return old32/64/88 positions. `frameBlend` remains appropriate for raw/debug consumers, but cannot authorize old precomputed case-shader tables for an after-blend analytic curve.

3. `profileTimes`/`heldFrameOf`/constructor held-map and `bracket` currently derive clear/void/collapse from raw cases. An analytic query needs explicit authored-sealing age, actual impact time, complete seal/retirement and local void data from its model. An old held raw frame is a sampling source, not the curve to draw/contact after it. Keep original event age fields separate where physics gates still depend on authored age; do not replace every life field with a new coverage clock. This candidate's `covered` boolean only means a roof envelope exists. It is not rider-local coverage and must not be passed directly to `tubeState`; actual projected geometry/void must answer that query.

4. `lipSheet.ts` has `tablesOf:WeakMap<BarrelCase,CaseTables>`, `caseTables` and `sheetTablesLookup`, which measure raw frames then blend their measurements. Those cached values are incompatible with joint after-parameter-blend geometry. Derive thickness/back/sky/formed and inner-face views from the final analytic query; cache that result for the prepared slice/query alongside the profile, keyed by all geometric parameters and age. Its explicit part ranges are outer32..60, cap60..68, inner68..80, root80..96, bridge96..102, plateau102..106, tail106..112. Existing fixed `SHEET`/`THROAT` classifications and `sheetAcross`/`throatViews` need tagged semantic support; their old index assumptions cannot silently shade/measure this new contour. Void/sky/overturn areas likewise must use the final queried curve and proper local air intervals, not cached raw case data or interpolated independent table values.

5. `SweptLoft` obtains its profile around `loftFront`'s query path and later separately gets drawing landmarks and cached sheet attributes. Use one analytic query/state per slice in both drawing/contact modes and carry its landmarks/part flags/coverage. Roof/contact must share formation and retirement. Do not use the old touchdown-plus-freefall collapse weight to remove a still-open analytic roof. Preserve explicit carrier/material-flow ages and existing alongshore world/ray mapping. Ordinary input preparation and physics startup are separate work.

6. `CrashCurve` currently caches `overturnAt(c.frames,heldFrame)` per case, requests the drawing profile, finds landing near the old face, and obtains held tip velocity through a TD clock. An analytic branch must use its actual cap-floor impact point/time, new sheet/void area and boundary derivative from the same shared query. Use the new cap64 semantics deliberately; raw `tipVelocities` are the old material64 and are not the new cap velocity. The geometry model derivative includes formation/seal/retirement, while world crest/ray/carrier transport is added by the existing mapping. Advective roof flow is a separate game approximation and must retain physical units (source velocity converts by sqrt(g*h0)); captured metre-space flow numbers are diagnostic, not physical velocity inputs.

7. Contact's quads may still be built from the128 final points, but raw landmark shortcuts assuming fixed old throat88/material64 or source sustained-overturn clocks must be tagged/migrated. `SweptProfileContact` must classify covered/loft from actual local rays/roof/void, then run the board/body sweeps against those exact quads. A positive maximum cross-section gap does not prove a1.25m footprint at a tilted board pose. Existing raw fixture and other-wave behavior require tests unchanged.

Cache fresh query results within a prepared mesh/contact scope and reuse them for `pointAt`, material tables, void and crash; use immutable source parameters as input, not a once-at-library-parse array rewrite. Build a bounded parameter/lifecycle cache only after measuring cost. The Python prototype has no allocation/cost claim. Its `phaseEnvelopeDerivative` is a F32 finite difference at fixed A/T and excludes carrier/parameter transport; it cannot alone replace the current physical fluid velocities.

## Required proof before source adoption

One new fully declared recipe must remove real crossings over all1224/3648 and the fixed phase/cross-case grids, match zero-state limits, classify contact roundoff, and preserve/create no false void. Test `profileAt`/`pointAt`/sheet/void/crash/drawing/contact equality and actual impact/retirement. Then native moving external and rider views must show an actual descending curl, maintained passage and continuous collapse on the ordinary Padang Big3.8m/18s playable case. A normal full-physics paddle/pop-up/entry ride needs body/board/roof sweeps and covered/loft/contact traces without pose teleport or forced state. Measure profile-query cost/FPS at ordinary settings. No build or native trial was started here.
