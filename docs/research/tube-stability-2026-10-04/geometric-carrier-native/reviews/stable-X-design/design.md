# Staged C stable-sampling design

Read-only design against `/private/tmp/tube-bounded-c-carrier-support-20261004/source`; no runtime, test, build, helper, native, port or Git action. This follows root's narrowed first-candidate scope: globally anchored X stations plus all raw parameter knots, retaining the existing final-run seal. It is a proposed isolated candidate, not visual/body/FPS/adoption evidence.

## Why this addresses the measured stress

The existing `SweptLoft.baseSlices` redistributes the complete raw sigma span plus both extensions over `ceil(span/spacing)+1` rows (`sweptLoft.ts:419–425`). Reacquiring an already dead X7 endpoint changes its X7–X9 arc length. All later raw sigmas then gain approximately the same constant, despite unchanged later crest coordinates. The existing whole-span grid changes its phase and spacing, shifts the first surviving row, and samples different sides of the raw age kink at X11. `sealRuns` then computes a different taper from that first stored surviving row (`955–1004`). The prior stress audit measured up to 15.547 ms interpolated mesh-age residual at X11 and 39.025 mm crest-Y residual at X12; these are different stations and mechanisms, while surviving raw ages changed at most 0.108 microseconds.

If the live row Xs are fixed, direct X interpolation uses the same raw bracket/fraction and raw parameter knots remain exact. The later sigma change is a common additive constant in exact arithmetic, which cancels in the seal distances `sigma(row)-sigma(firstLive)` and `sigma(lastLive)-sigma(row)`. Keeping `sealRuns` therefore removes this grid-phase mechanism without deriving a new retirement boundary.

This is conditional, not a universal continuity theorem. The supported raw roster, X/Z/H/D/age/pace controls, refinement decisions, front order, budget choice and overlap topology must be the same. The original raw-end weight at `sweptLoft.ts:649–654` must already be saturated: its distance to the *original* first raw endpoint need not cancel a changed dead upstream arc. That weight is saturated in the audited X11–12 stress neighborhood. Raw sigma words and `sliceSigma` are F32, so a constant double arc shift leaves bounded per-word rounding residuals; tiny fitter changes in raw age also remain. The provider's discrete event arithmetic prevents claiming exact geometric equality from merely small age differences.

## Valid X domain and station construction

Normal solver samples have fixed increasing column X: `ShallowWaterSolver.ts:245–246`, `crestOnset.ts:61–83`. Matched/new points use the sample's X; coasted points retain X (`BreakingFront.ts:309,327,388,417`). Linking follows adjacent increasing columns, and clock bridges append a later-column chain (`534–625`, `674–701`). Thus each ordinary contiguous C front has increasing X. `importState` does not establish the same coordinate contract (`653–670`), and dev packets are arbitrary. Validate every current C raw front rather than infer validity from its ID or history.

Validate finite F32 X/Z/sigma/tau/H/D, positive physical H/D, strictly increasing stored raw X and sigma. NaN pace retains the existing permitted missing-measurement semantics. Diagnose/skip unsupported monotonicity or precision domains consistently; never sort records or merge distinct raw controls to conceal a violation. RAW takes its existing path unchanged.

At the selected spacing `h`, use global world-X origin zero and integer lattice indices, with stations `Math.fround(j*h)` inside the actual extended X interval. Do not accumulate `x += h`, and do not rescale the lattice to the front span. Merge the sorted lattice with every raw X knot and both extension endpoints. At exact F32-X collisions, raw knots win; no approximate epsilon may erase a distinct raw knot. Eliminate duplicate stored X stations. A rounded collapsed shoulder must not create a duplicate-X strip; diagnose the precision case or explicitly omit that zero-width station.

Preserve the existing *arc-length* shoulder extension: if the first raw segment has `(dx,dz)` and length `L`, the left endpoint is `firstX - extension*dx/L`; the right uses the final tangent with the positive sign. Simply using `firstX-extension` would change geometry on oblique fronts. Endpoints retain endpoint H/D/tau/pace. Extrapolate X/Z along the original tangent, and assign the original endpoint sigma plus/minus extension. This preserves legacy shoulder behavior within its supported F32 domain.

Add a C `atX` sampler. Binary search by raw X, set `sample.x` to the exact chosen stored station X, and use `t=(X-Xa)/(Xb-Xa)` for Z/tau/H/D/pace and independently for sigma. At a raw knot, copy its raw words exactly. Outside the raw interval, hold endpoint physical parameters and extrapolate the geometric tangent. Do **not** map X into rounded sigma and call existing `at`; that can reintroduce parameter/position error. Include age-triggered refinement at the X midpoint of a chosen adjacent pair, with the same F32-X deduplication, not its sigma midpoint. The existing RAW `at`, `baseSlices` and refinement bodies remain unchanged.

In `sweptLoft.ts`, add C front validation/extended-X metadata in `fronts`, a reusable C station merge and `atX`, then C dispatch in `build`, `survey`, `refinements` and `planRays`. Drawing, ordinary contact and normal-demand contact must use this same station/sampling plan, including existing lazy height/seal behavior.

The old `CrestRayPlan` precision certificate assumes a nominal minimum sigma spacing of approximately 0.214286 m (`crestRays.ts:4–9,70–71,134–138`). A raw knot can be arbitrarily close to a global lattice station; that assumption no longer applies. Add an explicit optional C sampled-column preparation/proof (for example `prepareStoredColumns` or an optional stations argument on `prepareRecords`) instead of silently retaining this bound for the new loft. Preserve the existing default `prepare/prepareRecords` path for crash/direct consumers and RAW. Validate source controls as before, then validate the actual stored station Xs and sigmas and use their actual positive delta-X/delta-sigma where a per-sigma diagnostic is needed. With C rays `[0,1]` (`292–293`), every profile vertex retains the chosen stored station X; both endpoint half-plane advances equal its stored positive delta-X. No two-ULP/minSpacing correction is required for X already selected in F32. `measureRayAdvance` remains the final joined-geometry check (`866–884`). Do not claim an old lower bound for an arbitrarily close pair. Also handle F32 `sliceSigma` collisions explicitly, rather than generating a silently degenerate distance interval.

## Budget and scratch behavior for the first candidate

Retain the current global budget policy for this isolated change: survey the new C base union, apply the same live/extra decision and spacing formula, omit optional age midpoints when budgeted, preserve the C raw-dead-before-clock-clamp guard (`551–559`), and retain the final hard live-row cap (`562`). Do not add a new dyadic budget policy in this first candidate. Under the stress's unchanged supported controls, station/raw-knot live counts and refinement conditions are stable, so its budget choice is stable as well. A different component changing that global choice is outside the guarantee.

All raw parameter knots belong to the planned union even when they are dead; dead rows still separate runs and do not consume geometry budget. If mandatory live knots alone exceed the cap, the existing front-order/prefix truncation is unavoidable: do not discard an *interior* raw knot and reconnect across it. Keep the new cut sealed by legacy `sealRuns`, expose the actual truncation in evidence, and qualify output knot coverage to the retained prefix. Adding mandatory knots can reach the cap earlier than the parent; that is a material candidate behavior to report.

Scratch count is based on the extended X lattice count plus raw knot count plus endpoints, with at most one optional midpoint per adjacent base pair. Preflight finite/safe station index/count arithmetic and grow reusable base/X/sigma/planned arrays geometrically before writing. The live output remains `MAX_SLICES`; survey scratch may exceed it, as the current long-front path already does (`374–377`). Count the union rather than assuming the old sigma-grid count. Do not allocate unchecked pathological imported spans. At supported normal grid extents, the loop is finite; unsupported input should fail with a clear diagnostic, not become a NaN/truncated survey.

## Continuous retirement taper remains a separate future question

Do not implement it in this first candidate. The relevant predicate is positive `collapseFade(tau(X), profileTimes(H(X),D(X)))`; retirement is touchdown plus collapse (`sweptLoft.ts:185–188`, `ProfileLibrary.ts:307–314`). The lifecycle samples rounded C parameters and a finite event solve (`boundedCProfile.ts:41–42,66–73,118–120`). It is not proved globally continuous or monotone in affine raw H/D/tau. Even a smooth concave sqrt(scale) lifetime with affine age can contain a live interior between dead endpoints; endpoint signs cannot locate all transitions.

If later moving-retirement native evidence establishes a separate visible pop, stable stations provide a place to refine an already detected dead/live transition with a bounded provider-consistent predicate bracket. That would be a bounded boundary approximation, not an exact/global root certificate. It would need an inserted zero-weight boundary row and shared draw/contact support to avoid opening a raised edge. Overlap and hard budget cuts are topology events with no provider zero crossing and must retain their own seal. No arbitrary extra lifetime, Y freezing, global smoothing or body workaround follows from this audit.
