The frozen parallel candidate should first receive the planned native visual comparison. Two source-derived physical couplings merit an isolated correction experiment afterward. This report is read-only; no source, tests, build, native process, browser, resources, ports or Git state were changed.

Speed authority

CrestKinematics.ts64-81 computes c_n = eta_t / |grad eta| and returns the direction n = -grad eta / |grad eta| at the selected falling/rising face. crestOnset.ts copies motion.speed directly into CrestSample.speed, discarding direction. BreakingFront.ts318-323 smooths that scalar for roughly 0.1 s into p.crestSpeed. Thus p.crestSpeed is normal propagation speed; its interface comment saying 'along its column' is inaccurate. SweptCrash.ts386-408 correctly describes the intended column conversion: after the existing normal-speed clamp, pace = c_n / max(PACE.leastRayZ, n_z). Its RAW oblique regression at SweptCrash.test.ts428-441 explicitly tests that intent.

For a planar moving crest, n_x X + n_z Z - c_n t = constant. Along a fixed X column, dZ/dt = c_n/n_z. This is the intersection speed, not the material-vector component c_n*n_z. A fixed cross-section drawing ray q=[0,1] does not rotate the physical solver crest and does not change that formula. The frozen candidate instead supplies q_z=1 as the denominator, reducing its column pace wherever the physical n_z is below 1. With c_n=4 and n=(-0.6,0.8), intended column pace is 5 m/s; frozen C gives 4 m/s. The discrepancy affects jetBase/jetPace, paced front coordinates, crest ownership windows, later sigma/clock fits and feedback. It is not merely a spray-direction change.

Minimal justified speed correction

Keep C drawing/contact/throw rays exactly [0,1], and separate C's physical n_z for the pace calculation. Use the direction returned by the existing crestMotion authority, not the stabilized drawing normal or motion.crestSpeed from CrashCurve.jetMotion (that is a distinct library-profile derivative).

A narrow implementation can query crestMotion at the original solver crest cell once in C paceThrow, before any new throw positions are finalized, use its direction.z when valid, then pass it to the unchanged pace clamp/division. Preserve the existing smoothed p.crestSpeed numerator and all RAW arithmetic. This adds no transport fields or ongoing per-frame sampling. The current source already records that original cell before its bulk new-throw finalization.

If fresh crestMotion can be missing while the tracker retains a historical p.crestSpeed, do not silently substitute the drawing ray's 1. Prefer retaining a small optional physical-direction-Z value alongside the existing speed as crestOnset/BreakingFront read the measurement, so the same observation can survive a missing later face. FrontState already copies optional point fields through import/export. The existing 9-field front record need not change: physical propagation is finalized into jetPace before serialization. This is a slightly wider but better matched data-path correction. An explicit fallback for truly unmeasured physical direction is still required: use the local pre-new-throw crest tangent as a geometric physical-normal approximation, with the existing leastRayZ=0.5 guard, and record that fallback. Do not use the whole-front stabilized RAW drawing ray as physical truth or silently reinterpret normal speed as column speed. Retain the existing wave-speed fallback and slow/fast clamps; do not change their thresholds or clamp the projected pace a second time.

Width authority

BreakingFront.sigma is arc length. SweptCrash.measureArc recomputes it from the final current point coordinates before slicing. CrashCurve.slice160 sets width to half the neighboring delta-sigma sum. That width currently drives prospective water funding, held-jet span, current swept-air volume, pour air and the crash overlap footprint. Under C's parallel ray, all cross-section planes have constant X. Parameterizing the volume as (X(s), Y(s,u,v), Z(s)+u) gives perpendicular Jacobian |dX/ds|, not 1. Therefore projected X span is the consistent local extrusion width.

The smallest correction is C-only width = ((k>start ? p.x-prev.x : 0)+(k+1<end ? next.x-p.x : 0))/2, leaving the original arc formula byte-exact on RAW. Keep sigma, clocks, end weights, profile sampling and budgets unchanged. Sorted strictly increasing X is already the component invariant; do not hide reversed inputs with abs, a width floor or a clamp. At n_z=0.8, an arc cell of 1.25 m has X width 1 m; the old water/air/footprint span is 25 percent wider. At 45 degrees the ratio is sqrt(2).

This repairs the known orientation Jacobian in the existing local slice quadrature. Area(s)*width remains a local approximation when profiles, live water, end fades and ages vary; it is not proof of exact whole-mesh volume integration. End-cell centered footprint placement is also an existing approximation. Those limitations do not justify retaining a systematic arc-width inflation on parallel C.

Bounded tests for the isolated correction

1. Use actual synthetic travelling planar solver faces with physical n_z=1,0.8,1/sqrt(2), and both signs of n_x; assert crestMotion reports the expected direction and normal speed. With C drawing q=[0,1] and c_n=4, assert column paces 4,5,4*sqrt(2). Do not validate the projection only by mocking a drawing ray.
2. Exercise unmeasured direction and retained historical direction separately. A narrow-angle n_z below0.5 must retain the existing denominator guard. Assert the normal-speed slow/fast clamp occurs before projection and its counters remain correct.
3. Observe ordinary SweptCrash.update at a late first throw, before/after all new throws finalize, and through touchdown/retirement. Verify z=throwZ+jetPace*tau, original water-source cell retained, same-step order, paced no-jet ends, and fixed C draw/contact rays. Repeated updates must not re-pace an already thrown point.
4. Use a straight oblique front with delta-X=1 and delta-Z=0.75 (delta-sigma=1.25), then unequal neighboring X gaps and a curved front. C interior width should be1, end width0.5; RAW should retain1.25/0.625. Verify both signs of the crest slope and X/Z translation. In an untapered uniform profile, area*X span must be invariant when only Z slope changes.
5. Run the existing C120Hz prospective-water/open-air/closure/removal conservation fixtures on an oblique front as well as straight. Assert water funding, current void span, trapped dose and crash footprint use the same C X-width; compare to formula, not only internal ledger equality. With sufficient water supply, prospective asked volume should scale with X width. Preserve once-only trapping/release.
6. Preserve RAW exact snapshots/rays/pacing/width and packet layout, and any added physical-direction state through export/import. Add a remote split/relabel case with unchanged local physical direction to show its column pace and constant C ray stay unchanged.

These tests would establish the narrow projection/width correction. Native appearance, moving connected air and ordinary body passage remain separate acceptance evidence; no adoption-readiness claim is made.
