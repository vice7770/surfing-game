`cb.mjs` is, in full:

    // `?canyonWaves=true` reaches the game through `devTools.ts`'s `currentSearch()`, which reads
    // `globalThis.location?.search` -- so `location` must be an OBJECT with a `search`, not the string itself.
    globalThis.location = { search: '?canyonWaves=true' };
    await import('./m1-cpu-bench.mjs');

3.2y's and 3.2z's notes both write this as `globalThis.location = '?canyonWaves=true'`. A bare STRING has no
`.search`, so `currentSearch()` reads `undefined ?? ''`, `canyonBedSwitch()` returns `{}` and the bench silently runs
the DEFAULT Canyon while the operator believes it is running B -- no error, no warning, and a perfectly plausible
pair of hashes at the end. This round did exactly that on its first leg. WHAT GAVE IT AWAY was the grid the bench
prints: 400 x 507 = 202800 cells, which is the default Canyon's, against Canyon B's 400 x 451 = 180400. That first
leg is kept below as the default-Canyon leg, which is what it actually was and which is a leg this check needs
anyway; the two Canyon B legs below were run afterwards with the wrapper above.

A seatbelt that quietly measures the wrong thing is worse than no seatbelt, so the grid is now the first thing to
read in every leg's output, before the hashes.
