# Coarse fallback row range: conditional feasibility

This is a read-only audit of `/private/tmp/surf-tube-repair-combined-20261003`, the combined fog and late-water fallback candidate served on port 4208. Its durable source authority is the [combined patch](combined-repair/combined.patch) and [source manifest](combined-repair/source-manifest.json). Installed Three is version 0.186.1. Production was not changed, and this audit ran no tests, build, GPU work or timing probes. The supplied ordinary-run triangle medians were 1,371,717 before and 1,871,941 with the repair; that increase includes both repair meshes. A row range would affect only the coarse repair, leaving the original coarse draw and the entire Rich patch/skirt repair intact. It would retain two repair draw calls while reducing submitted coarse triangles. The size and performance value of that reduction are unmeasured.

The index layout makes the proposed subset inexpensive. `WaterSurface.ts:767` creates a `PlaneGeometry` and rotates it onto xz. Installed Three's `PlaneGeometry.js:66–99` emits vertices and triangle indices in increasing z-row order. Each strip has `6 * (nx - 1)` contiguous indices and `2 * (nx - 1)` triangles. A separate, lazily created `BufferGeometry` wrapper could reference the exact original attribute and index objects and change only its own `drawRange`: `start = firstStrip * 6 * (nx - 1)`, `count = stripCount * 6 * (nx - 1)`. No new index array, attribute copy, index upload or per-frame triangle traversal is needed. `WebGLRenderer.js:1223–1248` applies this contiguous range directly. Changing the original geometry's range would also crop the ordinary draw and is prohibited.

The geometric support is clear under the ordinary axis-aligned water transform. The vertex replacement at `WaterSurface.ts:345` changes only local y. Ordinary grid movement translates the coarse parent at line 412; its repair is an identity child (`541–560`). Therefore its final vertex x/z remains on the source grid. The dense patch has its own placement and skirt and must stay complete. Public transforms are broader than this ordinary contract: existing tests deliberately rotate the coarse parent (`WaterSurface.test.ts:342–346`). A culling implementation must conservatively use the full repair range when world z depends on local x/y, the transform or metadata is invalid, or a future shader moves x/z. It must also cover actual Float32 vertex and matrix rounding rather than assuming exact `zMin + row * spacing` arithmetic.

The fallback can survive only where the sampled mask is positive: `barrelMaskGlsl.ts:26` discards inactive masks or values less than or equal to the nonnegative dither. The node-centred sampler is at lines 13–15; both filters are linear, without mipmaps (`WaterSurface.ts:750–755`). A positive node at mask row k can contribute out to one mask spacing on either side. If the first and last positive rows are k0 and k1, the ideal continuous support lies between `maskZMin + (k0 - 1) * maskSpacing` and `maskZMin + (k1 + 1) * maskSpacing`. Clamp-to-edge extends support outward if a positive row reaches an edge; retaining the corresponding coarse end handles that case. Include complete coarse strips intersecting this interval, plus an explicit conservative rounding allowance. The mask grid can be finer than the water grid, so its spacing must not be confused with coarse spacing.

Fresh union bounds can be produced without adding a scan. `rasterizeBarrelMask` clears its destination (`barrelMask.ts:14`), processes all indexed triangles, keeps the maximum positive value on overlap (`41–43`) and already scans the final nodes to count nonzero entries (`47–48`). Fold min/max positive row collection into either the positive writes or that existing count traversal. Use the actual quantized nonzero bytes, not only triangle bounds or the most open front. Return explicit fresh bounds with the raster result; never infer freshness from a reused mutable array identity. Public `setBarrelMask` calls without validated bounds should retain the full repair range.

The required invalidation path is small but important:

1. Install mask bytes and corresponding bounds before synchronizing the repair. Current `setBarrelMask` synchronizes at line 492 before copying bytes at 494; a new range cannot be selected from stale data in that ordering. Null/empty input must invalidate bounds. Existing short-array calls leave the destination tail unchanged, so absent an exact-length validated result they need the full range.
2. Reset bounds whenever `refreshBarrelMaskGrid` changes origin, spacing or dimensions (`725–746`), including the same-size origin change that clears existing bytes. A resized source replaces coarse geometry at `682–684`; replace/rebind the wrapper's shared references and row layout then. Do not let `syncBarrelFallback:524` overwrite the wrapper with the original geometry.
3. Held cache hits in `SweptBarrel.ts:89–94` skip rasterization. They should reuse the last explicitly prepared range without a scan. Fresh builds at `98–101` install mask and bounds together. Disable/enable, restore/new source, look changes and camera changes must preserve the same original visibility and cache semantics.
4. Keep wrapper allocation lazy, as the repair already is. Additional constructor UUID allocation previously changed ordinary menu seed selection in an unrelated rejected FFT candidate.

Shared-buffer disposal needs special handling. `WebGLAttributes.js:204–220` caches buffers by attribute object identity, so sharing the original objects avoids duplicate uploads. However, `WebGLGeometries.js:8–37` deletes an index and every attached attribute on geometry disposal without reference counting, then releases that geometry's VAOs. Before disposing a wrapper while the original remains alive, detach its index and all shared attributes; dispose only its geometry registration/VAOs. Do this before disposing/replacing the original owner on source changes and final teardown. Otherwise disposing the wrapper could delete the ordinary water's GPU buffers. The patch repair should continue to share its original geometry as today.

There is a strict coverage limitation: this is not yet a proven exact culling candidate for the current MSAA renderer. `main.ts:216` enables antialiasing, and `vWaterWorld` is a normal smooth varying (`WaterSurface.ts:133`, `waterChop.ts:15`), without centroid interpolation. At a partially covered multisampled pixel, non-centroid interpolation may evaluate outside the triangle. Consequently a primitive whose vertex z range is outside mask support can still have a covered sample whose interpolated shader coordinate enters that support. A fixed extra row is useful for ordinary numerical error, but does not establish a general bound for grazing/sliver projections. This is a specification-level proof gap, not an observed visual defect. A guarded finite screen-to-world interpolation bound, with full-range fallback where it cannot be established, is required for strict unchanged-MSAA parity. Changing the varying to centroid or disabling MSAA changes rendering semantics and is outside this cull-only proposal. [GLSL ES 3.00, §4.3.9, printed page 50](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf).

Meaningful validation would extend the existing late-fallback tests at `WaterSurface.test.ts:237–385`, the mask raster tests and cached-draw tests in `SweptBarrel.test.ts`. Check disjoint fronts, a single positive row, boundary-positive rows, fractional/coarser grids, empty/null/short masks, mask shrink/grow, same-size origin changes, grid replacement, held/restore paths and transformed parents. Preserve all original attribute/index bytes, versions, draw ranges, vertex shaders, uniforms, material order and depth/stencil state; only the coarse repair's geometry wrapper/range may differ. Replace geometry-identity assertions with strict shared-attribute/index identity and test teardown order without shared-buffer deletion. A real GL check must confirm no additional buffer uploads and compare depth, stencil and native shaded output with the full-range repair, particularly at mask-edge pixels, near-plane crossings and grazing views. Do not infer visual parity from reduced triangle counts.

The likely eliminated work is coarse-repair vertex texture sampling, triangle setup and the cheap rejected-mask fragment path. Rich patch/skirt triangles remain, and fragments outside the mask already discard before costly optics. There is no established reduction in the physics critical path or measured FPS gain. The row layout is suitable, but the current interpolation proof and lifecycle requirements make implementation a separate decision rather than an automatic exact optimization.

A separate camera-frustum criterion can avoid that fragment-interpolation proof gap. Reject a complete row prism only when its full x extent and conservative displaced y interval are wholly beyond one clip half-space of the actual current view, with a conservative viewport/MSAA edge and arithmetic margin. Such geometry cannot rasterize into the current viewport, regardless of the later mask coordinate. With a global y interval, each plane's row-prism maximum is affine in row z; prefixes/suffixes can be excluded analytically and the remaining middle interval kept contiguous, without a triangle or full-grid scan. Keep any interior uncertainty. The range must follow the actual supplied camera/viewport on every draw, including `renderView`, rather than a stale own-camera range. A camera-derived range must never leak into a different view or any shadow pass; the original coarse draw would be a distinct future scope from the mask-only fallback proposal.

The current source contract does not publish a cheap conservative displaced-height interval. `SurfaceSource` at `WaterSurface.ts:194–219` supplies arbitrary written heights, and `update:403` has no extrema reduction. The static geometry bounds describe flat vertices; all water meshes intentionally disable frustum culling. Classic height is bilinear with an outside-grid zero (`115–122`), but Rich samples an overshooting Catmull-Rom surface (`water/cubicSurface.ts:42–67`) and then lowers it to a tube floor (`water/tubeCarve.ts:117–154`, `water/richWaterGlsl.ts:50–74`). Therefore a flat bounding sphere, assumed Hs envelope or even raw node min/max alone does not certify the Rich displaced prism. A future exact bound could be fused into an existing source-write traversal, then widened by proven cubic overshoot, current tube-carve and floating-point bounds; source/grid/look/tube changes must invalidate it. None of those conservative bounds is currently exposed. Without one, the general pitched/rolled camera cannot cheaply certify out-of-view rows, so this audit does not recommend enabling frustum row culling from existing public metadata.

## Optional concrete mesh budget and height bound

The immutable Rich patch constants are 96 m and 0.25 m (`water/richPatch.ts:5–8`). Its geometry always contains 385 × 385 interior vertices and a 1,536-vertex rim, even when its parent scale fits a smaller source grid. The index generator at lines 76–101 produces 294,912 interior triangles plus 3,072 skirt triangles: **297,984 triangles, 893,952 indices and 149,761 vertices** for the patch repair. Double-sided material does not double the submitted index count.

The original passive combination report retained render spacing 2 m, but no final init/grid or per-mesh counts; its 161 × 633 coarse dimensions were inferred from the 500,224 median triangle increase. A later canonical ordinary held capture now corroborates that layout directly, without substituting the differently sized T10 fixtures. The [lossless baseline source](../performance-2026-10-03/render-scale/baseline-held-source.json.gz) retains a **161 × 633 render grid at 2 m**, an independent **321 × 1265 mask grid at 1 m**, and actual scene geometry of **101,913 coarse vertices / 606,720 indices / 202,240 triangles** plus **149,761 Rich vertices / 893,952 indices / 297,984 triangles**. These are original water meshes; the isolated repair shares their geometry. The source was captured at sea 400.69104655763266 in the [render-scale experiment](../performance-2026-10-03/render-scale.md), rather than at the earlier combination sample's final state.

The gzip SHA-256 is `95f3937160eff73a9c751fcbdc2246a811978b49be7dbbda0e56ed9dea69e584`; its decompressed JSON SHA-256 is `8e73b4d10d268081891d0bf89b93c6706b37617a6bea5543af443d6963443587`. Both stored and decompressed bytes were independently checked against the [archive manifest](../performance-2026-10-03/render-scale/manifest.json) and original temporary source. The confirmed total is **500,224 triangles**: removing every coarse-repair triangle would eliminate at most 40.4% of the extra repair triangles, or 10.8% of the earlier candidate's median submitted total. The 59.6% patch share remains complete. This corroborates only the mesh budget; it is not a causal GPU-time or FPS result and does not close the MSAA, displaced-height or lifecycle proof gaps above.

The real-arithmetic cubic bound is inexpensive once finite raw Float32 extrema m and M exist. For t in [0,1], the Catmull-Rom weights in `cubicSurface.ts:42–45` satisfy:

- `w0 = -t * (1-t)^2 / 2`, `w3 = -t^2 * (1-t) / 2`; their total negative magnitude is `N = t * (1-t) / 2 <= 1/8`.
- Positive mass is `1 + N <= 9/8`. In the tensor-product 2D lookup, negative mass is `Nx + Nz + 2*Nx*Nz <= 9/32`, and positive mass is at most `41/32`.
- Consequently all interpolated heights lie in **`[m - (9/32)*(M-m), M + (9/32)*(M-m)]`** in real arithmetic. Node clamping does not enlarge it. A strict GPU bound also needs an outward allowance for the shader's highp coefficient/dot/accumulation arithmetic and the later model/view/projection/clip arithmetic; the exact rational formula alone is not a verified floating-point clip bound.

For this ordinary swept Padang path, `PhysicalMode.ts:545–547` creates `SnapshotSurfZone` with `sweptBarrel: true`. Its `writeTubes` returns 0 (`SurfZoneHost.ts:172–173`), making `waterCarve` return its input immediately (`tubeCarve.ts:128–129`). Thus the generic tube-floor concern does not apply to this particular coarse repair. The coarse geometry's skirt attribute is all zero (`WaterSurface.ts:772–774`), so it has no skirt offset. Both analytic and FFT chop change only shading slopes/normals (`waterChop.ts:17–43`): their displacement-y contribution is exactly zero. The cubic interval plus verified arithmetic/clip padding would suffice here; a future generic implementation should conservatively retain full range whenever tube carving is active unless it supplies an additional verified bound.

For completeness, the tube shader admits a simple real-arithmetic lower bound rather than a guessed wave-height envelope. With scaled length L and width W, its depth is `W/2 + L*u*sin(tilt) + W*(3*sqrt(3)/4)*u*sqrt(1-u)*cos(tilt)` with u in [0,1]. Since `max(u*sqrt(1-u)) = 2/(3*sqrt(3))`, depth is at most `abs(L) + abs(W)`. A floor cannot be below `crest - abs(L) - abs(W)`; the edge multiplier is in [0,1]. For independently blended length, width and opening parameters, use global `crestMin - openingMax*(absLengthMax + absWidthMax)`, rather than the maximum of endpoint products, which can miss an interior product maximum. Combine that lower bound with the cubic lower bound and the shader's 1e6 sentinel, then include numerical padding. This assumes all packed values are finite and the existing valid interpolation range; invalid metadata must select full range. No such metadata/bound is currently exported, and active-carve support is not required for the proposed swept-only path.

The state acquisition is the main remaining cost blocker. There is **no `WaterSurface.writeHeight` traversal** in this source: `update:403` calls `PhysicalSurfaceSource.write:69–71`, which calls `SnapshotSurfZone.writeUniformSurface:166–169`; the ordinary no-carve path is a native `data.set(snapshot.surface)` copy. Obtaining m/M in the renderer therefore requires an additional height-channel pass, or replacing that native copy with a JavaScript loop. The worker does have an existing per-node emission traversal (`SurfZoneSimulation.writeUniformFields:1171–1188`); collecting extrema from the actual assigned Float32 `surface[o]` there would avoid another grid walk, but requires publication metadata and freshness plumbing beyond a geometry wrapper. Repeated held frames could reuse that metadata; same-time restore/status replacement, grid and source changes must still invalidate it. No timing has established that this extra per-snapshot work is repaid by coarse-repair culling. Given the limited primitive-count ceiling and the goal of simpler browser work, the current recommendation is to stop this row path unless a specific coarse-repair GPU cost measurement justifies the new bound/state contract.
